# 보정 루프 — 카카오를 기준자로 두고 GTFS 를 채운다 (2026-09-17)

**목표는 엔진이 아니라 데이터다.** 오차의 대부분은 아직 안 채운 자료에서 나온다
(합성 시각표 9개 노선, 추정 배차, 버스 구간 속도). 그래서 루프가 하는 일은
"GTFS 를 한 조각씩 채우고, 채울 때마다 카카오 기준으로 나아졌는지 확인하는 것"이다.

카카오는 **기준자**지 참값이 아니다. 우리가 카카오를 베끼는 게 아니라,
사람이 실제로 비교하는 대상과 얼마나 벌어져 있는지를 재는 데 쓴다.

## 1. 무엇을 재나

매 회차 `data/logs/accuracy.csv` 에 한 줄이 쌓인다.

| 지표 | 뜻 |
|---|---|
| `bias` · `mae` · `within3` | 문앞-문앞. 우리 중앙값 − 카카오 최솟값(분) |
| `net_wrong` | 카카오가 우리 **최솟값보다 빠른** 건수 = 우리가 모르는 길이 있다 |
| `luck_only` | 카카오가 우리 min~max 안 = 망은 맞고 배차 운 차이 |
| `we_optimistic` | 카카오가 우리 **최댓값보다 느림** = 우리가 낙관적이다 |
| `synthetic_lines` | 실측 시각표가 없어 배차로 도는 노선 수 — **데이터 완성도** |

구간 단위(승차만) 지표는 이미 배치가 `data/logs/progress.csv` 에 쌓는다. 둘을 같이 본다.

## 2. 카카오 표본을 어떻게 뜨나

카카오는 **대중교통 경로 공개 API 가 없다**([ENGINES.md](ENGINES.md)). 그래서 사람이 보는
화면을 그대로 본다 — 헤드리스 브라우저로 딥링크를 열고, 대중교통 탭을 눌러 대안 전부를 읽는다.

- `tools/kakao-collect.mjs` · 기본 하루 **25건**, 한 건마다 **20초 이상** 쉬고, 연속 3번 실패하면 그날은 멈춘다.
- "지금 출발"만 되므로 **수집 시각이 곧 출발 시각**이다. 그래서 08:05 · 19:05 두 번 돈다.
- 대안 중 **최솟값**을 취한다. 첫 줄이 최소가 아닐 때가 있다(09-09 표본 15건 중 3건, 최대 11분 차).
- **표본은 저장소에 올리지 않는다.** `data/verify/kakao/` (git 무시). 저장소에는 지표만 남긴다.
  OD 목록(`tools/od-pool.json`)은 우리가 고른 것이라 남긴다.

## 3. 루프가 도는 법

```
08:05 · 19:05   수집 25건 → odcheck → accuracy.csv 한 줄
매일 새벽        작업 한 조각 (아래 큐) → 다시 측정 → 좋아졌으면 커밋, 나빠졌으면 되돌림
```

작업 큐 — GTFS 완성 순서:

1. **T-09** 합성으로 도는 9개 노선에 실측 시각표
2. **T-08** GTX-A 실측 시각표
3. **T-11** 시간대별 배차 품질
4. **T-05** 09-10 에 벌어진 버스 편향의 원인
5. **T-07** 버스를 타야 하는 OD 로 검증셋 넓히기
6. **T-13** 경의중앙 급행

## 4. 안전장치

- **동결 표본** — OD 풀의 20%(`frozen: true`)는 루프가 안 본다. 과적합하면 여기서 티가 난다.
- **되돌림** — 변경 뒤 지표가 나빠지면 그 커밋을 되돌리고 왜 그런지 기록한다.
- **머지 조건** — 지표가 안 나빠지고 지도 회귀 검사(`tools/check-map-follow.mjs`, 10경로)를 통과해야 `main`.
- **공개** — 기존 가드 그대로(데이터 온전 · 코드가 `main` 과 같음 · 해시 변경 · 배포 성공).
- **수집 예의** — 하루 상한, 간격, 실패 시 중단. 결과는 비공개 폴더.

## 5. 왜 카카오를 그대로 좇지 않나

- 카카오는 **"지금 나가면"** 한 번의 뽑기고, 우리는 **"그 시간대에 보통"** 의 중앙값이다.
  배차 30분짜리 버스면 둘은 원래 15분쯤 다르다. 이건 버그가 아니라 정의다([OdCheck](../builder/src/main/kotlin/reach/OdCheck.kt)).
- 그래서 판정은 **min~max 구간**으로 읽는다. 카카오가 우리 최솟값보다 빠르면 그때만
  "우리가 모르는 길이 있다"로 본다. 그 건수(`net_wrong`)를 0 으로 만드는 게 목표다.
