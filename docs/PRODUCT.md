# 출세권 — 제품 기획

> 2026-08-31. 타겟을 아파트에서 **자취(1·2인가구)** 로 옮기면서 정리한 문서.
> 설계 결정과 근거는 [HANDOFF.md](HANDOFF.md), 여기는 "무엇을 만들 것인가".

---

## 1. 한 문장

**직장이나 학교를 찍으면, 통근 가능한 범위 안에서 내 조건에 맞는 동네를 찾아준다.**

매물을 파는 게 아니라 **동네를 정해주는** 도구다. 매물은 직방·다방으로 넘긴다.

---

## 2. 타겟

**자취생 · 사회 초년생 · 1~2인 가구.**

아파트에서 옮긴 이유:

- 아파트를 사고 파는 사람은 이미 **동네가 정해져 있다.** 학군·자산·가족 때문에 선택지가 좁다
- 반면 자취는 **어디든 갈 수 있다.** 제약이 통근 시간 하나뿐이라 "지역 좁히기" 문제가 가장 크다
- 그래서 우리 도구가 가장 크게 쓰이는 층이다

취급 매물: **원룸 · 투룸+ · 빌라(연립다세대) · 오피스텔 · 다가구**

---

## 3. 경쟁 서비스와의 자리

| | 직방 · 다방 | 호갱노노 | 네이버부동산 | **출세권** |
|---|---|---|---|---|
| 매물 | ⭐ 실매물 | 직방 연동 | ⭐ CP 매물 | ❌ 안 가짐 |
| 실거래가 | 있음 | ⭐ 강함 | 있음 | 있음 |
| 지도 필터 | 영역 그리기 | 단지 조회 | 영역 | ⭐ **통근 도달권** |
| 통근시간 | 단지별 조회 | 단지별 조회 | 단지별 조회 | ⭐ **지도 전체 필터** |
| 맞벌이/2인 | ❌ | ❌ | ❌ | ⭐ **교집합** |
| 편의시설 | 아이콘 표시 | 일부 | 표시 | ⭐ **조건 필터** |
| 타겟 | 전 연령 | 아파트 소유·매수 | 전 연령 | **자취** |

**우리만 하는 것 세 가지:**

1. **지도 전체를 통근 도달권으로 필터링** — 남들은 "이 집이 몇 분"이고 우리는 "몇 분 안이 어디"
2. **두 사람 교집합** — 커플·룸메이트가 각자 직장에서 통근 가능한 곳
3. **조건 기반 동네 추천** — 편의시설을 지도 위 아이콘이 아니라 **필터**로 씀

**남들이 이걸 안 만드는 이유:** 그들의 지표는 매물 조회수인데, 지역을 좁혀주면 조회수가 **줄어든다.** 구조적으로 우리 자리다.

## 4. 핵심 흐름

```
1. 어디로 다니세요?        직장/학교 역 선택 (지도 클릭 또는 검색)
       ↓
2. 몇 분까지 괜찮아요?     통근 시간 · 출근/퇴근 기준
       ↓
3. 뭐가 중요해요?          편의시설 조건 (선택)
       ↓
4. 여기가 좋겠네요         동네 추천 + 시세 + 매물 링크
```

한 화면에서 위→아래로 흐르되, 각 단계가 **즉시 지도에 반영**된다.
"제출" 버튼을 누르고 기다리는 흐름이 아니다 — 이미 슬라이더가 즉시 반응한다(계산 90~190ms).

## 5. 데이터

| 층 | 소스 | 상태 |
|---|---|---|
| 통근 도달권 | 자체 계산 (시간 의존 Dijkstra) | ✅ |
| 아파트 시세 | 실거래가 API | ✅ 16,504단지 |
| **동네 시세** (원룸·투룸·쓰리룸+) | 실거래가 API, 법정동 집계 | ✅ **1,768개 동** |
| 빌라·오피스텔 건물 시세 | 실거래가 API (지번 식별) | ✅ 62,244동 (지오코딩 진행) |
| 단독·다가구 시세 | 실거래가 API (동 단위) | ✅ 1,689개 동 |
| **편의시설** | 카카오 Local 카테고리 (반경 800m) | ✅ 5종 |
| **백화점** | 격자 스캔으로 만든 목록 (수도권 75곳) → 거리 | ✅ |

**동이 주 데이터인 이유**는 [ADR-14](HANDOFF.md#adr-14-지도의-주인공을-점에서-동네-시세로-2026-08-31).
건물 하나의 거래 두세 건으로 낸 중위값은 시세가 아니다.

**방 종류는 전용면적으로 나눈다.** 실거래가에 방 개수가 없어서 면적이 유일한 단서다.
원룸 ≤33㎡, 투룸 ≤50㎡, 그 이상 쓰리룸+. 정확한 분류가 아니라 **비교 가능한 구간**이
목적이다.

**확인된 사실:**

- 빌라·오피스텔은 `jibun` 이 있어 **건물 단위로 지도에 찍을 수 있다**
- 단독·다가구는 지번이 없다. **동 단위 시세**가 한계 — 개별 건물은 못 찍는다
- `monthlyRent` 가 있어 **전세/월세 구분**이 된다. 자취는 월세가 실제 기준이라 중요
- 카카오 카테고리 검색으로 편의시설이 잡힌다 (강남역 1km: 병원 849, 편의점 140, 카페 554, 대형마트 7)

**정직하게:** 우리가 주는 건 **시세**지 실매물이 아니다. "이 동네 원룸이 대략 얼마"까지가 우리 몫이고,
실제 방은 직방·다방에서 본다. 그 경계를 흐리지 않는다.

## 6. UX 원칙

직방·다방·호갱노노를 보면 공통점이 있다.

1. **지도가 주인공.** 패널은 지도를 가리지 않는다
2. **입력이 즉시 반영.** 로딩 스피너를 보여주지 않는다
3. **모바일 우선.** 하단 시트, 엄지 도달 범위 안의 조작
4. **정보 밀도는 줌에 따라.** 멀면 요약, 가까우면 상세

우리가 지킬 것:

- 등시선은 **부드럽게 페이드인** — 값이 튀는 게 아니라 자라는 느낌
- 마커는 **스태거 등장** — 한꺼번에 튀어나오면 산만하다
- 패널은 **하단 시트(모바일) / 좌측(데스크톱)**, 접을 수 있게
- 색은 **도달시간 하나에만** 씀. 편의시설·매물은 형태로 구분한다

## 8. 더 붙일 만한 것

**바로 가치가 큰 것**

- **공유 링크** — 조건을 URL 에 담으면 커플이 서로 보내며 고른다. 리텐션이 구조적으로 약한 우리에겐 유입 경로가 된다
- **막차 레이어** — 야근 후 귀가 가능 여부. 자취생에게 실제 제약이고 아무도 안 보여준다
- **동네 요약 카드** — 클릭하면 "원룸 월세 중위 55만, 편의점 12개, 병원 3개, 강남 32분"

**막차 레이어를 보류한 이유 (2026-08-31)**

야근 후 귀가 가능 여부는 자취생에게 실제 제약이고 아무도 안 보여준다. 만들고 싶었지만
**지금 데이터로는 거짓말이 된다.** 우리 배차표는 전 노선 운행 종료가 00:40 으로 균일한데,
실제 막차는 노선마다 크게 다르다(경춘선은 훨씬 이르다). 노선별 차이를 흉내 내면 화면이
데이터보다 확신에 차게 된다. KTDB GTFS 로 실제 시간표를 붙일 때 함께 한다.

**나중**

- 소음(공항·철도), 경사도(언덕), 치안
- 전세사기 위험 신호 — 다가구 근저당 비율 등. 자취생에게 실제로 큰 공포지만 데이터 확보가 어렵다
