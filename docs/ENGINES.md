# 등시선을 만들 수 있는 엔진·API 조사 (2026-09-16)

"우리 RAPTOR 말고 남이 만든 걸 쓰면 되지 않나"에 답하려고 한 번에 조사했다.
후보마다 1차 자료(코드·문서·약관)를 열어 확인했고, 주장마다 반박을 시도하는 검증을 한 번 더 돌렸다.

## 우리가 필요한 것

| 요구 | 왜 |
|---|---|
| **동네 1,768곳의 분 값** (폴리곤 아님) | 목록·순위·예산 슬라이더가 전부 값에서 나온다. 그림은 값으로 그린다([ADR-34](HANDOFF.md)) |
| **도착 시각 기준** | 출근 슬롯 7개가 "몇 시까지 도착"이다. 전체 20슬롯 중 7개 |
| **이탈 도보 분** | 도보 상한 슬라이더가 그걸 거른다 |
| 출발 시각 5회 표본 | 배차만 아는 노선의 위상이 답을 1/3 정한다([ADR-33](HANDOFF.md)) |
| 미리 계산해 정적 사이트에 올려도 되는 권리 | 서버가 없다. GitHub Pages |

## 결론 먼저

- **한국이라서 막히는 건 없다.** 자가호스팅 엔진은 우리 GTFS + OSM 만 넣으면 지역을 안 가린다.
  막는 건 (a) 버전, (b) 출력 모양(폴리곤이냐 값이냐), (c) 상업 API 약관이다.
- **엔진을 바꿀 이유는 여전히 없다.** 남의 엔진도 같은 GTFS 를 먹으므로 데이터 오차가 그대로 따라온다([ADR-31](HANDOFF.md)).
- **대조군(오라클)으로 쓴다면 1순위는 MOTIS 2, 2순위는 R5(r5r).** OTP 는 후보에서 뺀다.
- **상업 API 는 우리 구조에서 불가.** 미리 계산해 정적 사이트로 서비스하는 것 자체를 약관이 막는다.

## 자가호스팅 (우리 데이터로 우리가 돌린다)

| 후보 | 1,768점 값 | 도착 기준 | 도보 분해 | 상태 |
|---|---|---|---|---|
| **우리 RAPTOR** (현재) | ✅ | ✅ (그래프 뒤집기) | ✅ | 매일 밤 657역 × 20슬롯 × 5표본 |
| **MOTIS 2** | ✅ 실험 엔드포인트 / 정식은 정류장까지 | ✅ 1급 | ❌ | MIT · C++ · 윈도 바이너리 · 2026-09-10 v2.11.3 |
| **R5 (r5r)** | ✅ | △ 흉내 | ✅ 구간별 | MIT · R + JDK 21 **정확히** · CRAN 2.4.0 (2026-05) |
| OTP 2.2~2.5 TravelTime | ❌ 폴리곤·격자만 | ✅ 2.3+ | ❌ | 2.6 에서 삭제(#5890) · 배차+도착 조합 NPE |
| OTP 2.6~2.10 | ❌ 일대다 없음 | — | — | GraphQL 에도 대체 없음 |
| OTP 1.5 Analyst | ✅ PointSet | △ 미검증 | ❌ | Java 8 · 6년 방치 |
| Navitia | ✅ heat_maps | ✅ | ❌ | 서비스 5개 · Debian 11 전용 빌드 |
| GraphHopper reader-gtfs | △ 내부만 | ✅ | ❌ | 임의 지점 API 없음 |
| Valhalla multimodal | △ | ❌ | ❌ | 도착 기준 없음 · frequencies 사실상 1창 |
| Naviqore / trRouting / nigiri / ULTRA | 후보별 상이 | 상이 | ❌ | frequencies 미지원, 별도 스택 필요 등 |

**MOTIS 2** — `GET /api/v6/one-to-all` 이 정식 API 로 있고 `arriveBy=true` 면 역방향 RAPTOR 를 돈다.
우리 출근 슬롯과 그대로 맞는다. 정류장 단위라 동네 값은 우리 도보 결합이 필요하고,
임의 좌표를 그대로 받는 `/api/experimental/one-to-many-intermodal` 은 아직 실험 경로다(기본 상한 128, 설정으로 올림).
출발 시각 창이 없어 표본 5회는 호출 5회다. 도보 분해는 안 준다.

**R5 (r5r)** — `travel_time_matrix()` 가 지정 지점들까지의 분 값을, `expanded_travel_time_matrix(breakdown=TRUE)` 가
접근·대기·승차·환승·**이탈 도보**를 나눠 준다. 우리 도보 슬라이더까지 재현할 수 있는 유일한 후보다.
다만 도착 기준은 흉내다 — 도착 시각에서 최대 소요시간만큼 뺀 출발 창을 훑어 가장 늦은 출발을 고른다.
R 런타임이 필요하고 JDK 는 21 이어야 한다(코드가 `ver != 21` 로 막는다). JVM 에서 `R5RCore` 를 직접 부르는 길도
있지만 문서·Maven 아티팩트가 없다.

## 상업·공공 API (한국 대중교통)

| 후보 | 대중교통 등시선 | 한국 | 막는 것 |
|---|---|---|---|
| TravelTime (traveltime.com) | ✅ 일대다 있음 | ✅ 대중교통 "Full" | **결과 캐싱이 기본 계약에 없음** — 별도 계약 + 60일마다 갱신 + 종료 시 삭제. 무료 등급은 외부 사용자 제공 금지. 게다가 한국은 도보·자동차 커버리지가 "None" |
| ODsay LAB | ✅ `searchPubTransIsochrone` | ✅ | 폴리곤만 · 10~60분 상한 · 시각·도착 기준 없음 · 결과 복제/저장/가공 무단 시 이용정지 · 비상업 목적 한정 |
| TMAP 대중교통 | ❌ A→B 만 | ✅ | 우리 격자를 채우려면 하룻밤 1억 건대 호출 |
| Kakao / Naver | ❌ 자동차만 | — | 대중교통 경로 API 자체가 없다 |
| Google Routes | △ 행렬 있음 | 미확인 | 결과 미리 받아 저장 금지 · 구글 지도 아닌 지도와 함께 못 씀 |
| HERE / Mapbox / Stadia / Geoapify / Targomo | ❌ 또는 미확인 | 대부분 미지원 | 대중교통 모드 없음, 또는 시각 지정 없음·60분 상한 |

**약관이 핵심이다.** 우리 방식은 "밤에 미리 계산해서 정적 파일로 올려 두고 계속 서비스"인데,
상업 API 약관은 대체로 그 저장·재배포를 막거나 별도 계약을 요구한다. 자가호스팅에는 그 문제가 없다.
